True Edit Phase 8: one-fixture live SetPositions proof

Browser check of the patched PDFium 2.15.1 engine on a single deterministic fixture (WAVESKERN -> TOKYOLAKE, standard Helvetica, WinAnsi, ASCII). The engines are identified by SHA-256, the rejected legacy layout is used as a gated control that proves SetPositions actually moves glyphs, and the Run #10 anchored layout is checked with exact extraction, search, geometry, render and save-structure gates. A pass here covers this fixture only. It is not evidence that arbitrary user PDFs, fonts or Unicode text are production-ready.

Fixture only

Safety boundary

No user PDF can be loaded. This page mutates only a deterministic, hash-pinned test fixture in browser memory. It does not change production editor files or either PDFium vendor folder. The proof is refused if any cross-origin resource loads or any unexpected script runs on this page.

What this proof does not exercise

For this fixture the unchanged prefix and suffix are empty (prefix 0, suffix 0), the replacement has the same length (9 glyphs), width fitting is off, Tc and Tw are 0, Tz is 100, the font is non-embedded standard Helvetica with WinAnsi encoding and the text is ASCII A-Z. Prefix anchoring, suffix shifting, width fitting, Tc/Tw/Tz, embedded TrueType, CID fonts, non-ASCII text, length changes and regeneration of untouched objects that carry kerning or Tc/Tw are covered only by the Run #10 CI suite, not by this page.
