NoblePDF engineering lab - Phase 10

Real-PDF corpus harness (local only)

Choose PDFs from this computer. Each file is read with the browser File API and analysed here with the same Run #10 PDFium engine, PDF.js 3.11.174, independent parser and Phase 9 gates as the fixture suite. Every direct text object is classified SUPPORTED, BLOCKED (with every Phase 9 gate code) or UNKNOWN. A supported object can be edit-tested through the full Phase 9 transaction and verifier; only a fully verified result replaces the working copy. Engineering diagnostics only: nothing here is the public editor.

Local only - no upload

Safety boundary and preflight

Selected PDFs never leave this browser: there is no upload code, the CSP allows no cross-origin connection and no form submission, and a network guard loaded before everything else records every request and refuses any request that carries a body. Corpus processing stays disabled unless the engine, PDF.js, CSP, script and network checks all pass and no service worker controls the page.

      6. Export corpus report

      The export is a JSON diagnostic report for aggregating many PDFs. By default it contains no PDF bytes, no file names, no document text, no reason details (details can quote document text) and no raw Producer/Creator strings (only the generator family). Hashes, counts, codes, font facts and text-state numbers are always included.
